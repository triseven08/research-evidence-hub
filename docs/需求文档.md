# 研知台需求文档

v0.5｜2026-11-04｜用户已确认开工，平台开发与验证中

## 定位

主题为“知识挖掘与探索”。向初次接触该领域的用户科普 Agent、工具调用和相关前沿方向，将已有调研组织成知识库、学习路径与探索案例。

用户进入网站后，应能找到感兴趣的问题、按顺序学习基础知识、追溯原始资料，并通过答疑和实验理解方法的能力与局限。内容以易懂的讲解和阅读体验为中心。

平台以整理和解释公开评测证据为主；团队自行跑分是可选扩展，本次不建设在线跑分调度器。本文和另外两份资料、接入文档供两位开发者及其 Agent 使用，不增加角色矩阵、任务认领和重复协作流程。

## 用户流程

| 入口 | 用户要完成的事情 | 对应内容 |
|---|---|---|
| 知识库 | 查概念、理解原理、查看资料 | 分类、搜索、正文与来源 |
| 学习路径 | 从基础逐步理解 Agent 与工具调用 | 有顺序的课程单元、先修关系、前后篇 |
| Benchmark | 对照工具评测及模型表现 | 评测介绍、来源、模型成绩与工具调用回放 |
| 阅读中的提问入口 | 解释当前概念、比较方法、追问资料 | 根据已审核知识回答并引用 |

全局导航保持“知识库 / 学习路径 / Benchmark”。问答通过明确的“提问”入口进入，可作为独立页面或阅读侧栏；不在页面各处重复放聊天窗口。首页直接呈现搜索、学习入口和精选内容，避免宣传区占满首屏。

## 内容与功能

### 知识库

按 Agent 基础、工具调用、MCP 与工具发现、规划与上下文、评测与前沿组织内容。支持关键词搜索和分类筛选，条目标题直指用户问题。

每篇采用“问题或概念 → 直观例子 → 工作机制 → 限制 → 延伸阅读”的结构，按实际内容保留必要章节，不机械套用全部小标题。术语有中文说明，代码和调用图只在有助于理解时出现。

每条关键结论附原始来源、版本或日期；研究事实、团队解释、待验证方向可辨。首版至少 8 篇已审核短文，不将长报告原样堆到网页。

### 学习路径

首版至少一条 4–6 个单元的完整路径，覆盖 Agent 是什么、工具如何调用、MCP 怎样连接工具、如何发现工具和组织多步任务。另可提供进阶和前沿路径。

路径以关卡地图呈现阅读顺序，进入同一知识正文，避免维护两套文章。每关配一道基于正文的概念题，答对后点亮节点，推荐首个未完成关卡；允许自由进入任一关。同篇文章在所有路径中共享通关状态，已有按路径保存的记录合并读取，不要求重复答题。进度保存在当前浏览器 localStorage，无需登录，刷新和返回地图后仍能继续。文章保留所选路径及上一关、下一关和返回地图入口，独立知识阅读不套用入门路径的顺序。暂不开发账号同步、正式考试、付费课程、证书或后台编辑器。

### Benchmark 与实验

围绕大工具目录的发现、复杂规划与失败恢复、上下文与工具定义管理、可复现评测等方向展开。每个方向回答“要解决什么问题、已有方法怎样做、还缺什么证据”，链接官方论文和项目，注明核验时间；不使用没有充分依据的“最先进/唯一/全面领先”。

首版收录 LiveMCPBench、ToolBench、HumanMCP 和 MCP-tools / MCP-Zero。每项展示测量目标、工具和候选规模、检索与执行流程、评分、限制、来源及横向对照。四项覆盖端到端调用与检索、模型主导查询与检索器提供候选等不同设置；工具库规模与每题候选数分开标注。

成绩按来源、实验对象和条件分组，不跨指标混排：LiveMCPBench 论文与官方榜单分开，ToolBench 保留方法、参考方案和子集，HumanMCP 与 MCP-Zero 显示论文实验而非实时榜单。记录获取日期与来源，未知信息标“未记录”；许可不明确的数据只提供来源入口。团队自测可用于补充缺失模型或理解流程，但不是必交成果，也不与外部成绩混为一谈。

### Benchmark 工具调用回放（预先录制）

这是最初提出的可视化测评展示需求。首版计划提供至少一个典型 benchmark 任务的预录工具调用轨迹，作为 benchmark 或实验详情中的可进入模块；不再只用“动画是加分项”概括整个功能。更复杂的动画、多个案例和模型轨迹对照按工期扩展。

对可公开的作者轨迹审核并脱敏，发布后由前端读取固定事件数据；团队未来实测可按同样规则导入。访客点击播放不会重跑 benchmark、请求模型或实际执行工具，也不消耗 DeepSeek 额度。

- 展示任务目标，以及“发现/检索工具 → 选择并调用 → 工具返回 → 后续调用 → 最终答案或失败”的可观察过程。没有发生的阶段不补造。
- 以步骤列表、时间线或简洁调用链组织，突出当前步骤；可展开查看工具名、脱敏参数、结果摘要、状态与实际耗时，帮助用户理解调用关系和失败原因。
- 提供播放/暂停、上一步、下一步、重置和进度定位；速度调整为可选增强。暂停时能停留阅读详情，播放结束后可重播。
- 关联 benchmark、模型配置、run/task/attempt 标识和评分依据，用户能从结果进入对应回放，并返回相关知识文章。
- 回放可以压缩等待时长，但实际耗时单独显示，不把动画速度当作测量时间。播放器不展示私有思维过程。
- 采用 Notion Style，布局与当前步骤高亮表达流程，避免额外装饰说明和重复副标题；动效限制在回放区域，保持正文阅读位置稳定。

三种来源必须分清：团队真实运行录制、作者公开历史轨迹、教学示意；后两者不得计入团队实测。HumanMCP 和 MCP-Zero 缺少可核验逐题日志，使用标注清楚的论文机制示意。播放真实记录不会新增一条运行或重复计入成绩。预先录制本身不等于虚构演示。

录屏视频可作为补充和现场备用；完整需求是能够查看步骤与调用细节的回放，不能仅以一张结果截图或一段没有事件详情的视频替代。缺少可用轨迹时明确标为素材未提供，不静默删除入口需求或伪造成功过程。

### 带引用答疑

以 DeepSeek API 为生成服务，由后端检索已审核文章和已发布实验资料后，把相关片段交给模型。用户不需要自备 API Key，浏览器不能访问站点密钥。

优先解释知识和引导阅读，回答简短、可追溯。系统提示词包含项目定位、知识库主题与实际条目、学习路径、助手能力及功能边界；问候、一般交流和本站功能介绍直接回答，不附“资料不足/仅供参考”。课题相关问题优先使用检索证据；没有充分依据时仍调用模型解释，由后端补上“未检索到足以支持此回答的知识库依据，以下结论仅供参考”，不能把模型常识当作库内证据。检索命中但片段无关或仅部分支持时同样适用。具体成绩、团队实测、训练数据或实时信息未知时不编造。来源有分歧时交代版本与条件，引用点击后定位具体正文；页面不展示模型私有推理。

首版按单轮问题实现；从文章发起提问时可附当前文章 ID，但不能据此跳过检索和证据检查。预设问题指向真实内容，预设答案不能充当实时模型回复。

问答历史保存在当前站点的浏览器 localStorage，保留最近 50 条提问及其回答、引用、文章上下文和失败状态，同时保存输入草稿与当前查看的记录。支持关闭重开、跨页面及刷新恢复；查看历史不请求模型、不消耗额度。刷新中断的请求显示未完成，不自动重试；存储失败时保留当前会话内容并提示。

## 视觉：Notion Style

**尽可能保持简洁。不要添加任何不必要的说明文字、二级标题或二级说明，优先让页面布局展示信息。** 通过分组、对齐、留白和位置关系表达层次；布局已经能说明的内容，不再重复配文字。删除后不影响理解和操作的说明应当删去。

已选择 [StyleKit Notion Style](https://www.stylekit.top/zh/styles/notion-style)，已查看规则与 Showcase。采用文档工具式的阅读结构：浅暖灰侧栏、白色正文、深灰文字、细边界、克制的悬停和小圆角。

| 元素 | 本项目规则 |
|---|---|
| 主体结构 | 桌面左侧目录、右侧正文；必要时增加轻量文章目录或问答侧栏，手机折叠导航 |
| 配色 | 侧栏/辅助底色可用 `#f7f6f3`，正文白底、主要文字 `#37352f`，少量强调色服务于链接与状态 |
| 排版 | 中文正文约 16px、行高约 1.7，系统无衬线字体；文章容器建议 720–820px，按实际中文阅读调整 |
| 组件 | 列表使用行，文章使用正文，实验使用表格；不将所有内容套进卡片 |
| 动效 | 约 150ms 的颜色或透明度变化；不使用悬停上浮、缩放、边框跳变和阅读区位移 |
| 控件真实性 | 只做阅读时不添加伪编辑框、拖拽手柄、“新建页面”或任务看板 |
| 信息密度 | 不添加装饰性二级标题、英文眉题、口号、无意义统计和重复说明，让布局表达关系 |

输入标签、表格列名、来源、指标单位、错误提示及无障碍名称是必要内容；文章本身的章节也应保留。颜色和图标不能成为状态的唯一表达方式。

不整段照抄参考页 Prompt/CSS。该页部分示例与其动效限制相互冲突，本项目以阅读稳定性和上述规则为准；低对比度灰字、亮色按钮上的白字需要单独检查。

## API 调用额度

用户确认需要限制访客用量，并在测试时提高次数。以下配置已由服务端实现，采用 D1 持久化与原子预留；浏览器不能修改额度。

| 限制 | 正式环境 | 私有测试环境 |
|---|---:|---:|
| 每位访客每日生成请求 | 100 次 | 1000 次 |
| 每位访客每分钟生成请求 | 3 次 | 20 次 |
| 全站每日生成请求 | 1000 次 | 3000 次 |
| 每位访客同时生成 | 1 个 | 1 个 |
| 全站同时生成 | 2 个 | 2 个 |
| 全站每日费用护栏 | 5 美元 | 5 美元 |
| 单次输出上限 | 2000 tokens | 2000 tokens |

全站每日 5 美元为用户确认的费用上限，不是已发生的消费或自动充值授权。达到次数或费用任一护栏即停止新增调用；测试提高次数不自动提高费用上限。具体核算见 [接入方案](知识库与模型接入方案.md)。

首版无登录，“用户”按服务端签发的匿名访客标识计数，同时使用可信来源 IP 限流；换设备、清除 Cookie 等情况无法做到严格的人级识别，因此还必须有全站硬上限。

测试额度仅适用于本地或受访问控制的私有测试部署，由服务端 `APP_ENV=testing` 选择。公开体验环境使用正式配置，不能用 URL、请求字段或浏览器开关切换测试额度。

问题无效、未检索到资料、缓存命中或调用前被限额拦截时，不消耗新的模型调用次数。实际发出的上游请求占用额度；超时和失败不盲目重试，避免未知计费重复发生。

问答输入处只显示必要的剩余次数，额度耗尽时说明恢复时间。全站上限或服务不可用时保留内容浏览。每日按北京时间 00:00 重置，接口提供剩余额度、重置时间和错误码。

## 完成标准

- 8 篇以上已审核知识文章，至少一条完整学习路径；搜索与分类可组合，前后篇和来源链接有效。
- Benchmark 内容能解释研究问题和证据边界；评测组产物接入后可追溯配置、样本、评分和案例。缺失结果不伪造。
- 至少一个 benchmark 预录回放能从结果或案例入口打开；播放/暂停、前后步、重置与进度定位有效，事件顺序和显示详情与记录一致。
- 回放在模型/API 不可用时仍能播放，不发起模型或工具执行请求，不占生成额度；真实运行与教学脚本标识准确，统计不随播放次数变化。
- 使用 15 题检查答疑：10 题有依据、3 题无依据、2 题来源冲突；至少 12 题正确且证据充分，无依据的课题回答附参考提示且不编造成绩，引用均可定位。另验收“你好”“介绍一下你的功能”“介绍一下知识库有什么内容”，均应自然回答且不附参考提示。
- 本地模拟验证正式/测试额度差异、并发计数、午夜重置、费用上限、缓存不重复扣次和无法由客户端开启测试模式；验证限额不需要消耗真实 API。
- 手机与桌面都能顺利阅读和提问；页面无冗余副标题、重复说明或无功能装饰控件。
- 密钥没有进入 Git、前端 bundle、日志或录屏。公开部署具备真实的限额存储和费用护栏，而非仅在页面显示计数。

首版实现采用 React / TypeScript、Vinext 的 App Router 与 Cloudflare Worker，正文、外部成绩和回放用 JSON 管理，D1 存储额度与缓存。四项 benchmark 信息和来源分组成绩与公开轨迹摘要纳入网站。

本次已对照本聊天核对：已有调研知识库、学习路径、带引用答疑、外部 benchmark 介绍与结果、可选的团队自测、预录工具调用回放均保留；视觉采用 Notion Style 并优先以布局表达信息；DeepSeek 密钥隔离、正式/测试额度与每日 5 美元费用护栏保留，不恢复多余协作文档。
