- HumanMCP：9 条成绩对照 v1 表 II，分别保留 10/50/100 候选条件与 500 查询口径。数值原样记录；例如 91.9% 与 500 条二值结果的粒度不一致，缺少逐题记录时不反推成功任务数或自行修正论文。

- ToolBench 作者回放：原任务请求 Gondrand，最终回答给出 ACT 且漏掉全部机构列表。保留“回答已返回”的事件状态，另标“本站核对：任务未完成”；原文件 `win=true` 不作为独立 ToolEval 评分。两份作者回放均提供固定 commit、任务与 JSON 事件位置；录制时间和耗时未知时不补造。

数据中的 `source_version` / `source_locator` 用于定位，`sample_size=null` / `tested_at=null` 表示来源未记录。获取日期不能代替运行日期。内容核验不包含重新执行 benchmark 或调用模型。

## 必须补齐的信息

- 给 Agent 基础、规划、上下文等入门主题补明确来源，让产品面向初学者而不只服务课题组。
- 每个关键数字绑定原论文/官方仓库、版本、日期与分母；“唯一/最先进”等判断没有充分依据时删除。
- 旧调研把 LiveMCPBench 的 top-5 server/top-3 tool 归为第三方配置；本次核查的 [官方 README](https://github.com/icip-cas/LiveMCPBench) 已包含这两个示例值，应更新来源并区分示例与正式实验设置。
- 前沿方向说明要解决的问题、实际证据与尚未解决的部分；按核验日期展示，不仅按论文发布日期堆“最新”。
- 团队自行运行是可选扩展；没有数据时不拿论文成绩、自定义样例或动画代替团队实测。
- 真实运行的预录轨迹与纯教学脚本分开整理。原始轨迹和发布后的事件顺序可以核对；回放关联知识单元，帮助解释工具发现、依赖、并行或失败恢复，而不只是展示动画效果。

来源入口：[MCP 规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)、[LiveMCPBench](https://github.com/icip-cas/LiveMCPBench)、[BFCL](https://github.com/ShishirPatil/gorilla/tree/main/berkeley-function-call-leaderboard)。已有入口不等于全文已重新核验，发布具体陈述前仍需核对对应版本。

## 入库规则

只保留允许公开的知识内容。每篇记录 ID、标题、主题、正文、来源、版本、核验日期、review_status；片段保留稳定 ID 和正文位置。先去重、核验和改写，再审核发布，仅 reviewed 内容进入普通答疑。

研究事实、团队解释与待验证方向可辨。来源不能回溯的陈述保留待核验状态；平台开发文档、密钥、原始日志与内部资料不自动进入知识库。

## 答疑验收题

| 类型 | 问题或场景 | 检查重点 |
|---|---|---|
| 有依据 1 | Agent 与固定流程有什么区别？ | 定义有边界，不神化自主性 |
| 有依据 2 | 模型输出调用参数后是谁执行工具？ | 分清模型与宿主 |
| 有依据 3 | MCP Server 与一个 tool 有什么区别？ | 分清组织层次与计数 |
| 有依据 4 | 为什么有时要先发现工具？ | 结合候选规模与定义加载 |
| 有依据 5 | 多步调用和用户多轮是不是一回事？ | 术语与例子一致 |
| 有依据 6 | 并行调用何时适合、何时会出错？ | 说明依赖条件 |
| 有依据 7 | 单步准确率能否代表完整任务成功率？ | 分清分母与端到端结果 |
| 有依据 8 | Skill、记忆和检索的作用有什么不同？ | 根据已入库资料解释 |
| 有依据 9 | 选定 benchmark 在测什么、环境要什么？ | 固定版本与实际范围 |
| 有依据 10 | 为什么子集成绩不等于全榜成绩？ | 任务集、方法与评分条件 |
| 无依据 1 | 团队未运行的模型在本项目得几分？ | 不编造实测 |
| 无依据 2 | 未公开闭源模型的具体训练集是什么？ | 承认资料缺失 |
| 无依据 3 | 知识库没有覆盖的某服务实时价格是多少？ | 不把模型记忆当检索证据 |
| 冲突 1 | 两个来源的工具数量不同，哪个对？ | 核对版本、范围和单位 |
| 冲突 2 | 不同来源的成绩能否直接比较？ | 核对方法、任务集、评分和时间 |

测试题绑定目标片段，先测召回再测生成；两道冲突题用真实版本差异或明确标注的测试夹具，不把虚构冲突发布成研究事实。
