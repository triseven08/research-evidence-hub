# 模型与知识库方案

2026-11-03。已接通 DeepSeek 后端问答，不依赖知乎直答或托管知识库。真实密钥只在被忽略的本地配置与部署平台 Secret Store 中。已完成 15 道验收题及两道修复复测，共 16 次上游请求，按峰时费率保守核算约 0.0053 美元；这不是服务商余额或最终账单。

## DeepSeek 接入

已核对 [官方接入文档](https://api-docs.deepseek.com/)、[模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode) 和 [Chat API 参数](https://api-docs.deepseek.com/api/create-chat-completion)。

| 配置 | 首版建议 |
|---|---|
| 基础地址 | `https://api.deepseek.com` |
| 生成接口 | `POST /chat/completions` |
| 模型 | `deepseek-flash`，本次官方文档将它映射到 DeepSeek-V4.1-Flash-1017；实际调用记录返回模型与时间 |
| 思考模式 | 明确发送 `thinking: {type: "disabled"}`，避免采用默认思考配置 |
| 输出 | 显式发送 `max_tokens: 2000`，不依赖较大的默认上限 |
| 输入 | 问题最多 2000 字符；输入预算默认 12000，按完整消息 UTF-8 字节数保守限制并预留 128 字节封装余量；指令和问题本身超限时在调用前拒绝 |
| 密钥 | 服务端读取 `DEEPSEEK_API_KEY`，不使用 `NEXT_PUBLIC_` 变量，不传浏览器 |

按本次官方价格页，Flash 每百万 tokens 的峰时费率为：未命中缓存输入 0.30 美元、输出 1.20 美元；非峰时为其一半。实现按峰时未命中价预留，并按实际 usage 与相同保守费率结算，不依赖低峰或缓存折扣；账本可能高于实际扣费。当前服务端仅接受 `deepseek-flash`，更换模型前须同时更新费用核算。价格会变，不能把这份记录永久当作服务商承诺。

首版只调用生成接口，不启用收费联网搜索、抓取、模型自行调工具或自动批量补充资料。标为知识库依据的回答来自本项目已审核内容，模型常识补充作为参考回答展示。可选的团队 benchmark 实测使用独立配置与用量记录，不混入访客的每日计数；共享同一密钥时，项目侧护栏无法覆盖外部脚本消费。

## 资料与回答链路

```text
审核短文 → 按语义切分并保留出处 → 本地检索索引
用户问题 → 检索相关片段（允许为空）→ 加入项目背景 → 检查缓存与额度
         → 服务端调用 DeepSeek → 校验回答依据与引用 → 回答 + 可用来源链接
```

闭源模型通过请求上下文取得资料，不会自动读取本地文件，也不需要为此微调。先用词法检索验证，embedding 和向量服务按检索缺陷决定是否增加。

离线整理时，每篇保留 `document_id`、正文、分类、来源链接、版本、核验日期和 `review_status`。按自然段落与表格语义切分，初始可尝试每段 400–800 个中文字；每段使用稳定的 `chunk_id` 和正文锚点。仅 reviewed 内容进入检索；四项 benchmark 的审核正文也可检索并链接详情锚点。原始实训目录、开发提示词、密钥和日志不递归入库。

在线按词法相关度召回最多 5 段，加入中文/英文术语映射，按完整消息预算裁剪。检索为空也进入正常模型调用流程，不在本地直接返回“资料不足”。2026-11-04 起，系统提示词提供可信项目背景：知识库分类与实际条目、学习路径、Benchmark 和预录回放功能、助手定位及能力边界。分类、条目和路径名称从发布内容生成，具体检索证据继续放在 user 消息中。

模型按语义返回 `basis`：`knowledge` 为片段充分支持的知识回答，`project` 为基于可信背景的本站介绍，`general` 为问候及一般交流，`reference` 为缺少充分片段支持的课题回答。检索到片段不代表问题一定有依据，混合问候与课题问题按课题部分选择类型；不额外调用一次模型做分类。`reference` 由后端统一加上“未检索到足以支持此回答的知识库依据，以下结论仅供参考”，其他类型不加该提示。允许模型用已有知识解释，但不允许编造具体成绩、训练数据、团队实测或实时事实。

服务端为本次证据建立 `[S1]` 到 `chunk_id` 的映射；`knowledge` 必须有正文引用和有效 ID，其他类型允许空引用。所有类型的未知引用都拒绝；参考回答可引用部分片段，但未被片段支持的内容不能伪装成库内结论。有效 ID 只证明来源存在，仍需人工验收结论是否被原文支持。前端显示“根据知识库回答 / 研知台助手 / 参考回答”，本地历史保留类型并兼容旧记录。

概念提示结构：规则、证据、用户问题分开；证据中的命令仅作内容；资料缺失时不补造，版本冲突时解释条件；答案后引导阅读相应文章。前端链接由服务端映射生成，不信任模型自行编造的 URL。

## 存储

知识正文、路径、方向介绍和实验快照继续用 Markdown / JSON 管理，无需为内容展示引入数据库服务器。

额度计数是另一类需要写入的状态。即使内容来自文件，生产环境的限额也不能只存在进程内存：进程重启、多个实例或并行请求都会破坏计数。

- 单机且具备持久磁盘：可用 SQLite，使用事务处理额度预留、结算与幂等键。
- Serverless / 多实例：使用支持原子计数和持久化的共享 KV / 数据库，按实际部署能力选择。
- 内存计数只供本地模拟和开发；公开体验前必须验证真实部署的存储、原子操作和重启行为。

已选择 Cloudflare D1。迁移和额度触发器保存在 `drizzle/`；请求以原子 batch 进行预留，再结算 usage。数据库不可用时暂停生成。开发预览的数据库与线上库彼此独立。

## 额度与费用控制

所有判断都在服务端，在调用模型前完成。当前值见 `.env.example`：正式访客 100 次/日、测试访客 1000 次/日；全站分别 1000/3000 次，每日费用上限均为用户确认的 5 美元。当前实现只在 loopback 主机名与 `APP_ENV=testing` 同时成立时启用测试额度；线上即便误设 testing 也使用正式值。

匿名用户使用服务端生成且签名的访客 Cookie；再对可信代理提供的来源 IP 做辅助限制，不直接信任任意 `X-Forwarded-For`。IP 独立配置：正式环境暂定 500 次/日、10 次/分钟，私有测试环境 3000 次/日、60 次/分钟；校内共享 IP 测试时检查误限情况。它不是严格的账号级配额，清理 Cookie、代理变化等无法彻底识别人，因此全站次数和费用限制不可省略。

一次生成的处理顺序：

1. 校验输入、请求幂等键与访客标识；检索并形成证据版本签名。
2. 相同完整消息（包括项目背景、问题、证据）、模型和提示版本命中 24 小时内缓存时直接返回；不新增模型请求，也不扣生成额度。`assistant-v3` 与旧提示缓存隔离。问候、功能介绍和无依据课题回答的新生成均计入调用次数；参考回答缓存保留参考提示。
3. 在同一原子操作内检查并预留用户分钟/日额度、IP 额度、全站日额度、并发槽位与最坏费用，不能先查余额再异步递增。
4. 当前按 UTF-8 字节数保守限制完整消息，并给消息封装留余量，不依赖客户端 token 估计。费用用 `input_budget × 峰时未命中输入价 + output_cap × 峰时输出价` 预留。
5. 请求发出后占用调用次数；根据实际 usage 结算费用，释放未用预留与并发槽位，写入脱敏账本。
6. 本地校验失败且未发出请求时释放预留。请求超时或计费状态未知时保守保留该次计数/费用预留，不盲目退款或自动重试；后台核对后再结算。

以默认配置计算，一次请求的保守预留为 `(12000 × 0.30 + 2000 × 1.20) / 1,000,000 = 0.00600 美元`，全站每日 5 美元上限及输出上限不变。旧部署如显式设置 `API_CONTEXT_MAX_TOKENS=4000`，升级时应调整为 `12000`。这是限额计算示例，实际费用由服务商计量；token 估计误差、价格更新和站外用量也必须考虑，不能把它宣传成保证不会超出的服务商账单硬上限。

服务端限制必须 fail closed：共享计数或费用存储不可用时暂停生成，知识浏览继续；不因后端出错切成无限调用。按北京时间 00:00 切换日期桶，跨日的在途请求继续记入开始时的桶，避免重置与并发竞态。

记录请求 ID、访客标识的非可逆摘要、计数、tokens、估算/实际费用与错误类型，不记录密钥、Authorization 头或完整敏感问题。调用上限、费用上限和缓存统计分别展示，不能把缓存命中当作新增付费调用。

## 前后端最小接口

知识、学习与实验内容由文件提供；以下接口已实现。

- `POST /api/ask`：`{question, article_id?, request_id}`。返回 `{status, basis, answer, citations, quota}`，status 为 answered / insufficient_evidence，basis 为 knowledge / project / general / reference。
- `GET /api/usage`：返回当前访客的剩余次数、重置时间与当前是否可提问；不返回全站密钥或服务商账户余额。
- 限额拦截返回 HTTP 429；code 区分 `USER_QUOTA_EXCEEDED`、`RATE_LIMITED`、`SITE_QUOTA_EXCEEDED`、`SITE_BUDGET_EXCEEDED`，附 `retry_after`；`GET /api/usage` 提供 `reset_at`。
- 模型超时或服务不可用返回 504 / 503；前端提供简短说明，不静默切换收费模型或重复请求。

测试额度不能通过请求体、query、Cookie 自报或客户端按钮获得。无登录的首版不实现“开发者无限额账号”；需要公开测试时仍用正式护栏。

## 实验数据交接（可选扩展）

首版以外部公开成绩和来源为主，不要求团队运行 benchmark。论文、官方榜单和不同条件分别保存，不跨条件混排；原始论文、完整日志、未脱敏返回及未确认许可数据不公开。

评测组交付可公开的运行配置、样本 ID、逐题结果、脱敏事件与简短结论。平台侧核心字段为 `run_id`、benchmark 与上游 commit、模型/方法/评分器、时间、任务集和原始来源。导入包为 `{experiment,replays}`，完整可执行契约在 `lib/experiments.ts`，命令见 README；不额外维护重复的字段规范。

计划数 N 分为成功 S、任务失败 F、环境失败 I、评分失败 J、未运行 U，满足 `N=S+F+I+J+U`。展示成功分子分母与覆盖率；官方 scorer 分数沿用原名、原分母单列。token/费用缺失为 null，不填 0；子集不能冒充官方全量榜单。

轨迹只保留可观察事件：检索、调用、返回、最终答案和错误。正文解释它说明的知识点，而不是仅堆一张排名表；真实运行的预录与构造教学脚本按下方规则分别处理。

### 预录回放数据与播放

首版整理作者公开轨迹的可观察事件摘要；HumanMCP 与 MCP-Zero 使用标注清楚的论文机制示意。团队将来实测时可保存轨迹并离线转换为可公开的回放 JSON。原始记录留在本地忽略目录，发布产物只包含经过核对的脱敏数据。

| 字段 | 用途 |
|---|---|
| `id`、`origin` | 回放稳定标识与来源；逐题结果通过 `replay_id` 引用，origin 为团队 `recorded_run`、作者公开历史 `author_record` 或 `scripted_demo` |
| `benchmark`、`run_id`、`task_id`、`attempt_id` | 与运行、样本和具体尝试关联；教学脚本没有真实运行标识时为 null，不伪造 |
| `task`、`model`、`recorded_at` | 展示任务目标、模型和录制时间 |
| `events` | 按顺序保存的事件，包含稳定 event ID、sequence、类型、关联 call ID、相对时间、耗时与状态 |
| 事件详情 | 工具名、脱敏参数、结果摘要、最终答案或错误；需要时保留依赖/并行分组 |

只有构造的教学脚本属于 scripted_demo。作者历史轨迹属于 author_record，必须注明来源，不能关联团队运行；团队真实运行属于 recorded_run，可关联团队结果；播放器读取记录不产生新的 attempt，不改变已有统计。

前端以固定文件维护播放状态：当前步骤、播放/暂停、进度和可选速度。恢复、后退、定位或重置均从记录重建界面状态，不执行事件里的工具名、参数、命令或链接。暂停后保留详情，长结果按需展开；没有事件、素材损坏或关联记录缺失时显示简短状态。

回放读取与模型调用完全分开。播放和重播不访问生成接口、不占访客生成额度；模型密钥缺失、额度耗尽或上游故障时，已有回放仍可使用。实际耗时来自日志，播放节奏可压缩但不可回写测量结果。视频备用不替代事件数据和逐步查看能力。

## 知乎 AI Works 部署

本地《知乎黑客松技术指南》第 4 节提供了源码代部署流程：项目广场创建作品 → 选择“源码发布” → 将页面给出的打包提示词和命令交给 Agent → 上传 ZIP → 在带 preview 的作者预览地址测试 → 确认发布，审核通过后获取正式公网链接。本文档未包含平台专属打包命令，应以实际“源码发布”页面提供的配置为准。

指南说明：代部署适用于前端 + Node 后端且不含数据库写入的项目，暂不支持独立数据库托管。当前项目的文章、路径和轨迹已采用 JSON；额度、费用与缓存仍依赖 D1，运行时也使用 Cloudflare Worker，不能把整个项目直接当作通用 Node 项目打包，也不能把原子额度账本改为普通 JSON 写文件。

若使用 AI Works 托管页面，需要先确认其 Node 版本、启动/构建方式、服务端密钥注入方式，以及是否允许调用外部后端。可保留独立、公开可访问且具备限额存储的问答后端，再适配同源代理或受限跨域访问；当前所有者私有的 Sites 地址不能直接供匿名知乎访客调用。若平台支持外部数据库，也可另行适配，未确认支持前不移除现有护栏。

公开仓库和交付 ZIP 均排除真实密钥、本地数据库与原始日志。指南中的“将密钥写入文件直接构建”不适用于当前交付方式；密钥应由部署平台的服务端配置提供。

## 最小验证

2026-11-04 助手体验更新：43 项本地测试、类型检查、变更文件 lint 和生产构建通过。通过本地生产构建接口完成 6 道真实调用验收（问候、助手介绍、知识库介绍、空检索课题、混合问候与课题、库内引用），再对简短问候与纯文本输出复测 3 题，均通过；使用持久化本地 D1 账本及原有每日 5 美元上限。全项目 lint 仍有其他未修改页面的 13 项既存错误及 1 项警告，未纳入本次修复范围。

先用本地模拟验证限额、缓存、并发和错误路径；这些验证不需要真实 API。真实接入时先 1 次最小文本请求，再用少量自有证据题验证引用，记录模型和 usage 后再决定是否扩量；不自动跑满测试上限。

问答验收采用资料清单中的 10 道知识题、3 道无依据题和 2 道版本差异处理题。首次发现并行段落漏召回及 benchmark 介绍缺失，修复后两题真实复测通过。3 道无依据题均明确资料不足，没有编造实测或训练集；两道版本题回答比较条件，不声称已进行版本对照实验。20 项本地自动检查涵盖额度竞态、预算、缓存、故障、检索与导入，未消耗真实 API。另一台电脑不会通过 Git 获得本机密钥。
